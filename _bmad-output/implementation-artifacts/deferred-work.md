- source_spec: `_bmad-output/implementation-artifacts/spec-1-5-login-logout-session.md`
  summary: Every `apps/api/src/routes/auth.ts` handler that reads a JSON body (`register`, `login`, `dev-login`) crashes with a `500` instead of a `400` if the body is a literal JSON `null` (valid JSON, so `.catch()` on `c.req.json()` never fires, then `body.email` throws a `TypeError` on `null`).
  evidence: Found and verified during Story 1.5's review (edge-case-hunter, confirmed by direct code reading): `register`/`login` have zero body-shape guarding at all (pre-existing, predates this story); `dev-login` mirrors the same weak pattern for consistency. The global `onError` handler still returns a well-formed Problem Details `500`, so this isn't a raw crash - just the wrong status code on a body shape no real form ever sends. A proper fix (e.g., a shared `parseJsonBody` helper defaulting to `{}` for both `undefined` and `null`) should apply uniformly across all three routes at once, not be patched into one.
